# context-lab · 上下文管理三层策略 + 预算分配器

> 任务二交付物：**截断 / 滑窗 / 摘要压缩**三层机制 + **预算分配器**精化层的完整实现，
> 配一个 **25 轮客服长任务 × 5 策略 × 期末测验** 的 token 对比实验。

## 这是什么

长任务里上下文无限增长是 Agent 的时延与费用双重炸弹。本仓库把课堂上的
"上下文工程三层策略"落成可运行、可测试、可对比实验的代码：

```
第 0 层   system prompt + 安全条款 + 工具 schema   —— 每轮无条件前置，永不压缩
第 1 层   Truncation   截断：保头保尾，中段硬切（带显式截断标记）
第 2 层   SlidingWindow 滑窗：只留最近 N 条（朴素方案对照组：连 pinned 都保不住）
第 3 层   Summary      摘要压缩：窗口外老消息压进滚动摘要（语义保留，压缩有成本）
精化层    Budget       预算分配：每轮调用前按优先级装填 token 预算
                       （滚动摘要 > 近期对话 > 更老对话），pinned 决策点不可压缩
```

**不可压缩原则的落地**：关键决策点（客户确认改地址的回合）打 `pinned` 标记，
Budget 策略宁可记录 `pinned_overhead`（预算溢出量）也不丢弃它——这就是
"工具 schema、关键决策点、安全边界条款不可压缩"中"决策点"一条的可执行版本。

## 快速开始

```bash
pip install -e .                          # 或 pip install -e ".[dev]" 带测试
cp .env.example .env                      # 填入 OpenAI 兼容 API Key（默认智谱 GLM）
python -m context_lab --dry-run           # 零费用验证管线（假客户端+规则压缩器）
python -m context_lab                     # 真实实验：5 策略 × 25 轮 + 期末测验
python -m context_lab --report context_lab_results/results.json   # 只重生成报告
python -m pytest                          # 15 个测试，无需 API Key
```

## 实验设计（为什么这样设计而不是随手跑）

- **场景**：「山野杂货铺」客服，25 轮真实形态对话（含 3 个工具：查订单/查库存/改地址，
  改地址有副作用——所以每个策略从 `build_scenario()` 拿全新状态，跨策略零污染）。
- **事实分层埋点**：关键事实按深度分布（早期：礼物对象/颜色/镍过敏；中期：预算/期限；
  决策点：改地址，pinned；后期：预算上调），期末 6 题按同样深度抽样——
  各策略的"遗忘曲线"因此可测。
- **期末测验代替自评**：对话结束后关闭工具、只凭策略装配出的上下文回答事实题，
  命中率 = 记忆保持的客观度量，不靠"感觉还行"。
- **诚实记账**：输入/输出 token 一律取 API 返回的真实 usage；压缩调用的管理开销
  （overhead）单独记账；测验成本单独列。压缩是否"回本"在报告里直接可见。
- **dry-run 与真跑同一管线**：假客户端按场景语义应答（含发起工具调用），
  数字证明管线形状正确，不冒充实验结论。

## 产物（context_lab_results/）

| 文件 | 内容 |
|---|---|
| `results.json` | 全量原始数据：每策略每轮的 token 账单、工具调用、装配快照、测验明细 |
| `report.md` | 总账表（含"较基线节省 %"、"单轮峰值"）、测验命中矩阵、自动观察 |
| `tokens.png` | 左：每轮输入 token（看增长形态）；右：累计输入（看总账） |

## 模块地图

```
messages.py    Msg（含 pinned 元数据，to_api() 剥离进协议前）+ token 估算器
strategies.py  五策略 + Compressor 合同（本仓库核心资产）
agent.py       带工具调用的多轮循环 + 期末测验探针；每轮记账
scenario.py    25 轮剧本 + 3 个确定性工具 + 6 题测验 + 事实埋点
experiment.py  实验编排：策略 × 回合 × 测验，副作用隔离与落盘
report.py      report.md + tokens.png（缺 matplotlib 自动降级）
fakes.py       场景感知假客户端（--dry-run / 测试共用）
llm.py         OpenAI 兼容基座：usage 真实记账、注入缝、重试
config.py      12-Factor 配置（CONTEXT_LAB_ 前缀）
```

## 已知限制（诚实清单）

- token 估算器（CJK≈1/字、其余≈1/4）只用于策略决策与 dry-run 展示；
  一切账单数字以 API usage 为准，报告里不混用。
- 摘要质量依赖压缩 prompt 与模型能力，本实验只测"摘要机制的成本-记忆权衡"，
  不测评"哪个模型摘要更好"。
- 单场景单剧本：结论方向（滑窗省钱丢记忆/摘要用开销买记忆）可讲，
  具体百分比不可外推——那是把实验当真理，面试里这么讲会被追打。
