# context-lab · 长任务 Agent 上下文管理策略实验

针对长对话场景下上下文 token 线性膨胀、时延与推理成本双增的问题，实现并对比了**截断 / 滑窗 / 滚动摘要 / 预算分配**五种上下文管理策略，通过 25 轮客服长任务 + 6 题期末记忆测验，量化不同策略的 token 成本与记忆保留率。

## 项目背景

长任务 Agent 的上下文会随对话轮次线性增长，最终导致推理时延上升、token 成本超支，同时早期关键信息还可能被挤出窗口。

本项目将上下文工程的分层策略落地为可运行、可复现、可量化对比的实验代码，覆盖从朴素截断到智能预算分配的完整消融阶梯。

## 核心实验结论

基于 25 轮「山野杂货铺」客服长任务场景，对比结果如下（结论方向可参考，具体数值不可外推）：

| 策略 | 输入token | 较基线节省 | 管理开销 | 记忆命中 | 总成本 | 较基线总成本 |
| --- | --- | --- | --- | --- | --- | --- |
| 全量保留（基线） | 143,953 | 0% | 0 | 6/6 | 149,209 | 0% |
| 消息级截断 | 67,654 | 53% | 0 | 3/6 | 75,164 | -50% |
| 滑动窗口（最近8条） | 58,019 | 60% | 0 | 1/6 | 69,146 | -54% |
| 三层堆叠（工具截断+滑窗+摘要） | 62,655 | 56% | 162,136 | 3/6 | 231,269 | +55% |
| 三层+预算分配 | 54,615 | 62% | 58,038 | 6/6 | 118,918 | -20% |

### 关键发现
1.  **朴素压缩只省输入，不省总成本**：滑动窗口输入成本最低，但早期事实完全丢失；滚动摘要策略输入看似节省，但管理开销是输入节省的 2 倍，总成本反超基线 55%，属于「花更多钱，买半份记忆」的负收益。
2.  **预算分配实现性价比最优**：同样基于三层截断，通过优先级装填 + pinned 关键决策点保留，在输入节省 62% 的前提下，记忆保持率达到和全量基线一致的 6/6，总成本反而比基线低 20%，实现了「降本不降效」。
3.  **压缩不是层数越多越好**：消息级截断和三层堆叠摘要同为 3/6 记忆，但后者多消耗 16.2 万 token 的管理开销，说明无差别滚动重压缩会持续损耗信息，徒增成本。

## 策略分层设计

遵循「不可压缩原则」：system 指令、安全条款、工具 schema 为第 0 层，每轮无条件前置，永不压缩；在此基础上实现四层策略递进：

- **第 0 层**：system prompt + 安全条款 + 工具 schema —— 每轮无条件前置，永不压缩
- **第 1 层 Truncation 截断**：保头保尾，中段硬切（带显式截断标记）
- **第 2 层 SlidingWindow 滑窗**：只留最近 N 条（朴素方案对照组：pinned 消息也无法保留）
- **第 3 层 Summary 摘要压缩**：窗口外老消息压进滚动摘要（语义保留，压缩产生独立开销）
- **精化层 Budget 预算分配**：每轮调用前按优先级装填 token 预算 （滚动摘要 > 近期对话 > 更老对话），pinned 决策点不可压缩

**不可压缩原则落地**：关键决策点（客户确认改地址的回合）打 `pinned` 标记， Budget 策略宁可记录 `pinned_overhead`（预算溢出量）也不丢弃关键信息——这是 "工具 schema、关键决策点、安全边界条款不可压缩"中「决策点」维度的可执行实现。

## 实验设计
- **场景**：「山野杂货铺」客服，25 轮真实形态对话（含 3 个工具：查订单/查库存/改地址，改地址有副作用——每个策略从 `build_scenario()` 拿全新状态，跨策略零污染）。
- **事实分层埋点**：关键事实按深度分布（早期：礼物对象/颜色/镍过敏；中期：预算/期限；决策点：改地址，pinned；后期：预算上调），期末 6 题按同样深度抽样——各策略的「遗忘曲线」因此可被量化观测。
- **期末测验代替主观自评**：对话结束后关闭工具、只凭策略装配出的上下文回答事实题，命中率 = 记忆保持的客观度量，不依赖主观判断。
- **诚实记账**：输入/输出 token 一律取 API 返回的真实 usage；压缩调用的管理开销（overhead）单独记账；测验成本单独列。压缩是否「回本」在报告中直接可见。
- **dry-run 与真跑同一管线**：假客户端按场景语义应答（含发起工具调用），可零费用验证管线逻辑正确性，不冒充实验结论。

## 快速开始

```bash
pip install -e .                          # 或 pip install -e ".[dev]" 安装测试依赖
cp .env.example .env                      # 填入 OpenAI 兼容 API Key（默认适配智谱 GLM）
python -m context_lab --dry-run           # 零费用验证管线（假客户端+规则压缩器）
python -m context_lab                     # 运行完整实验：5 策略 × 25 轮 + 期末测验
python -m context_lab --report context_lab_results/results.json   # 仅重生成报告与图表
python -m pytest                          # 运行单元测试，无需 API Key
```

## 已知限制（诚实清单）

- token 估算器（CJK≈1/字、其余≈1/4）只用于策略决策与 dry-run 展示；
  一切账单数字以 API usage 为准，报告里不混用。
- 摘要质量依赖压缩 prompt 与模型能力，本实验只测"摘要机制的成本-记忆权衡"，
  不测评"哪个模型摘要更好"。
- 单场景单剧本：结论方向（滑窗省钱丢记忆/摘要用开销买记忆）可讲，
  具体百分比不可外推——那是把实验当真理，面试里这么讲会被追打。
