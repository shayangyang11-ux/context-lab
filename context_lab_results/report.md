# context-lab：25 轮长任务上下文管理对比实验

## 一、实验设置

- 场景：「山野杂货铺」客服长任务，25 轮 + 6 题期末测验
- 第 0 层固定成本（system + 工具 schema）：约 428 token/轮，已含在各策略 prompt_tokens 内 —— 这是所有策略都省不掉的地板
- 记账口径：输入/输出为 API 返回的真实 usage；管理开销（overhead）为策略压缩调用单独花费；期末测验成本单独列出，不混账

## 四、自动观察

- 最省输入：三层+预算分配（54,615 token）
- 总成本最低：滑窗（最近8条）（69,146 token）
- 记忆最好：全量保留（基线）（6/6）
- 三层堆叠（工具截断+滑窗8+摘要）：压缩管理花费 162,136，换回输入节省 81,298（未回本）
- 三层+预算分配：压缩管理花费 58,038，换回输入节省 89,338（回本）

## 五、分析框架（读数指南）

- 全量基线的单轮峰值随轮数近似线性增长 —— 长任务下时延与费用双杀；
- 滑窗最便宜，但早期事实直接丢（测验早期题应明显丢分）—— 省钱丢记忆；
- 截断保头保尾：开场约束还在，但中段事实（预算/期限）丢失；
- 摘要/预算用管理开销买记忆：看『节省是否覆盖开销』与『测验命中』两栏；
- 预算策略的 pinned 例外：关键决策点顶破预算也保留（Budget.pinned_overhead 字段观测这一代价）。
- 总成本口径下，压缩策略可能从「最省」翻转为「最贵」——管理开销是隐形账单。
